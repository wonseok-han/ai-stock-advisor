# timing-signal Plan

## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | 기존 AI 시그널은 방향성(상승/하락)만 제시하여, "지금 들어가도 되는 타이밍인지"라는 사용자의 핵심 질문에 직접 답하지 못함 |
| **Solution** | 기술 지표·가격 위치·시장 환경을 종합한 "진입 타이밍 조건 충족도" 판정을 AI 분석에 추가 |
| **Function UX Effect** | 종목 상세 AI 분석 페이지 최상단에 "지금이니?!" 타이밍 카드가 표시되어, 한눈에 진입 조건 상태를 파악 |
| **Core Value** | 서비스명과 일치하는 핵심 기능 제공 — 초보 투자자가 "진입해도 괜찮은 조건인지"를 팩트 기반으로 확인 |

---

## 1. Background & Motivation

### 1.1 현재 상태
- AI 시그널은 `STRONG_BUY/BUY/NEUTRAL/SELL/STRONG_SELL` 5단계 방향성 시그널 제공
- 단기(1~2주) + 장기(6개월~1년) 이중 관점 분석
- 기술 지표 해석, 뉴스 영향, 리스크를 종합 제공

### 1.2 문제점
- "지금이니?!" 서비스의 핵심 질문 = **"지금 들어가도 되는 타이밍인가?"**
- 현재 시그널은 "상승/하락 방향"을 말해줄 뿐, **진입 타이밍의 적절성**을 직접 판단하지 않음
- 예: BUY 시그널이라도 이미 급등 후라 진입 타이밍이 아닐 수 있고, NEUTRAL이라도 저점 근접이면 타이밍일 수 있음

### 1.3 목표
- 서비스명에 걸맞은 **"지금이니?!" 타이밍 판정** 추가
- 매수 추천이 아닌, **진입 조건 충족 여부를 팩트 기반으로 평가**
- 기존 방향성 시그널과 병렬 배치 (대체가 아닌 보완)

## 2. Feature Definition

### 2.1 타이밍 판정 구조

```
┌─────────────────────────────────────────────┐
│  "지금이니?!" 타이밍 판정                      │
├─────────────────────────────────────────────┤
│  판정: "지금이니?!" | "아직인듯?" | "흠.. 애매한데?"  │
│  조건 충족도: 72/100                          │
│  충족된 조건:                                 │
│    ✓ RSI 과매도 구간 (28)                     │
│    ✓ 52주 저점 대비 +5% 이내                   │
│    ✓ 거래량 급증 (평균 대비 2.3배)              │
│  미충족 조건:                                 │
│    ✗ 주요 이평선(MA20) 아래                    │
│    ✗ 시장 전반 약세 (VIX 28)                  │
│  한줄 요약: "기술적 저점 신호가 있지만,          │
│    시장 환경이 불안정해 분할 접근이 유리한        │
│    구간으로 보입니다"                           │
└─────────────────────────────────────────────┘
```

### 2.2 판정 기준 (Timing Verdict)

| 판정 | 조건 충족도 | 의미 |
|------|-----------|------|
| **지금이니?!** | 70~100 | 진입 조건이 다수 충족됨 — 관심 있다면 살펴볼 만한 구간 |
| **흠.. 애매한데?** | 40~69 | 일부 조건만 충족 — 명확한 신호 없음 |
| **아직인듯?** | 0~39 | 진입 조건 미충족 — 기다리는 것이 나을 수 있는 구간 |

### 2.3 진입 조건 팩터 (Timing Factors)

| 카테고리 | 팩터 | 판단 기준 |
|----------|------|-----------|
| **가격 위치** | 52주 저점 근접도 | 52주 저점 대비 +10% 이내 |
| **가격 위치** | 지지선 근접 | MA60, MA120 근접 또는 반등 |
| **기술 지표** | RSI 과매도 | RSI ≤ 30 |
| **기술 지표** | MACD 골든크로스 임박/발생 | MACD 히스토그램 반전 |
| **기술 지표** | 볼린저밴드 하단 접촉 | 하단 밴드 이탈 후 복귀 |
| **거래량** | 거래량 이상 급증 | 20일 평균 대비 2배 이상 |
| **시장 환경** | VIX 안정 | VIX < 20 (안정) |
| **시장 환경** | 섹터 상대 강도 | 해당 섹터가 시장 대비 강세 |
| **이벤트** | 실적 발표 후 안정 | 실적 발표 3일 이후, 급변동 없음 |
| **밸류에이션** | P/E 대비 할인 | 섹터 평균 P/E 대비 저평가 |

> 각 팩터는 충족 시 가중치에 따라 점수를 부여하고, 총점을 0~100으로 정규화

### 2.4 기존 시그널과의 관계

| 항목 | 기존 AI 시그널 | 타이밍 판정 (신규) |
|------|--------------|-------------------|
| 질문 | "이 종목 방향이 어때?" | "지금 들어가도 되는 조건이야?" |
| 결과 | STRONG_BUY ~ STRONG_SELL | 지금이니?! / 흠.. 애매한데? / 아직인듯? |
| 관점 | 방향성 (상승/하락) | 진입 적절성 (조건 충족도) |
| 근거 | 종합 분석 요약 | 개별 조건의 충족/미충족 목록 |
| 위치 | AI 분석 페이지 본문 | AI 분석 페이지 최상단 히어로 |

## 4. Technical Approach

### 4.1 Backend

**방식: Gemini 프롬프트 확장**

기존 AI 시그널 생성 시 Gemini에게 추가 JSON 섹션을 요청:

```json
{
  "short_term": { ... },
  "long_term": { ... },
  "timing": {
    "verdict": "NOW" | "NOT_YET" | "UNCERTAIN",
    "score": 0-100,
    "factors_met": [
      { "factor": "RSI 과매도", "detail": "RSI 28 — 30 이하 진입", "weight": 15 }
    ],
    "factors_unmet": [
      { "factor": "시장 안정성", "detail": "VIX 28 — 불안정 구간", "weight": 10 }
    ],
    "summary_ko": "한줄 판정 근거 요약",
    "disclaimer_ko": "진입 조건 충족 여부일 뿐, 매수 권유가 아닙니다"
  }
}
```

- 기존 `AiSignal` record에 `TimingVerdict` 필드 추가
- 기존 ContextAssembler가 이미 수집하는 지표/뉴스/가격을 그대로 활용
- 추가 API 호출 없이 프롬프트 스키마 확장만으로 구현 가능

### 4.2 Frontend

- `/stock/[ticker]/ai` 페이지 최상단에 "지금이니?!" 타이밍 히어로 카드
- 판정(지금이야/애매해/아직이야)에 따른 색상 + 아이콘 분기
- 조건 충족/미충족 팩터 리스트 (확장 가능)
- `/stock/[ticker]` 메인 페이지의 AI 링크 카드에 타이밍 배지 요약 표시

### 4.3 면책 처리

- "진입 조건의 기술적 충족 여부를 정리한 것으로, 투자 판단은 본인의 책임입니다"
- 기존 ForbiddenTermsRegistry와 동일한 금지어 정책 적용
- "지금이야" 판정에도 "확실한 매수 타이밍" 같은 확정 표현 금지

## 6. Risks & Mitigations

| 리스크 | 영향 | 완화 |
|--------|------|------|
| Gemini 응답에 timing 필드 누락 | 타이밍 카드 미표시 | fallback: timing 없으면 카드 숨김, 기존 시그널만 표시 |
| 판정이 자문으로 오해될 가능성 | 법적 리스크 | 면책 문구 고정 + 금지어 검증 + "조건 충족 여부" 프레이밍 |
| 프롬프트 확장으로 토큰 증가 | Gemini 비용 증가 | 기존 컨텍스트 재사용, 추가 토큰 ~200개 이내 |
| score 산출의 일관성 | Gemini가 매번 다른 기준 적용 | 프롬프트에 팩터별 가중치 명시, 팩터 목록 고정 |

## 7. Implementation Order

1. **BE: 프롬프트 스키마 확장** — `ai-signal.system.txt`에 timing 스키마 추가
2. **BE: 도메인 모델 추가** — `TimingVerdict` record, `AiSignal`에 필드 추가
3. **BE: 응답 파싱/검증** — `ResponseValidator`에 timing 필드 검증 추가
4. **BE: API 응답 직렬화** — Controller 응답에 timing 포함
5. **FE: 타입 정의** — `ai-signal.ts`에 timing 타입 추가
6. **FE: 타이밍 카드 컴포넌트** — 히어로 카드 + 팩터 리스트
7. **FE: AI 페이지 통합** — 최상단 배치
8. **FE: 종목 상세 배지** — 링크 카드에 타이밍 요약 표시
